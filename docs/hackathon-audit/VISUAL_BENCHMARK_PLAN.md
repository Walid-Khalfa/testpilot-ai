## 2. Crucial Architectural Insight from Benchmark Design

Look closely at **Scenario 4** and **Scenario 5** above:
1. **Why Vision Must NOT Override Deterministic `confirmed` Status:** If we allowed Muse Spark Open's visual critique to automatically create findings without strict gating, Scenario 5 (`success.html`) could easily suffer a false-positive finding (e.g., *"The form has no CSS styling on the page footer"*).
2. **Why `visualObservation` as Structured Reasoning Telemetry Is the Sweet Spot:** By surfacing Muse Spark Open's screenshot analysis as a dedicated `visualObservation` field inside the agent's step reasoning (and only creating findings via deterministic assertions), we achieve **zero risk of breaking the 0-finding control guarantee** while demonstrating true multimodal vision to the hackathon judges.
